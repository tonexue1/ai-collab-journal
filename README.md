# 协作观察 · DSH Collab Journal

**DeepSeek Harness 原生插件。数据来自 DSH 会话，界面在 DSH 内，解析使用 DSH 配置的模型。**

按实际交互日期，回看自己在各段会话中介入了什么、开口之前发生了什么。每次人的表达独立保留，模型整理分类和具体贡献，每一项都能回到原文；完整轨迹作为另一种阅读方式。[为什么做这个项目](docs/philosophy.md)

## 这一版

0.3.3 将日期和当日总结放在阅读页首。工作区以文字标签切换，左侧选会话，右侧按时间先读「此前情况」，再读「我补上的」。点击段内依据可核对对应原文，展开「分类依据」可核对模型为何作此分类。版本信息在页底。

- 在 DSH 侧栏打开「协作观察」。顶部默认选中今天，可用「上一天」「下一天」翻页，点击日期打开月历，或点「今天」返回。按本地时区和真人表达发生的时间归日，跨日会话在对应的每一天都可找到。选到没有表达的日期会显示空状态。
- 日期下方是「当日总结」。点击「生成当日总结」，可阅读当天主要在做什么、补充或纠正了什么。它汇总所选日期内**全部工作区**的交互，默认排除归档会话，勾选「包含已归档会话」后使用包含归档的范围。
- 在页面右上角「插件设置」，或 DSH「插件 → 协作观察」的配置区，打开「每日定时整理」并选择时间。默认关闭，预设为本地时间 21:00。开启后，每天先整理全部工作区当天非归档会话中新增或有变化的介入，再更新当日总结。
- 在总结下方选择工作区，左侧搜索和选择会话，右侧阅读个人交互或完整轨迹。「按日期」列出当天有真人表达的会话，「全部会话」还可查看这个工作区其他日期的会话。切换工作区和搜索只筛选下方列表。
- 每条卡片呈现时间、分类、具体标题、「此前情况」与「我补上的」。人的原话完整保留，默认折叠；分类和说明可打开生成时的原文依据。介入前材料可跨过午夜，不被日期切断。
- 分类包括方向纠正、任务指挥、上下文补充、流程推进、授权选择、结果反馈、新任务、未判定。可以按类别筛选；这些是 AI 整理，不能直接等同 AI 失败或自主运行能力评分。
- 点击「整理当天交互」或单条「整理这次交互」，使用该会话配置的 DSH 模型。浏览和刷新不会调用模型。先提供当前人的完整表达及附近前文，模型必要时补读更早依据，不从头概括整条调用链。中断等停止状态优先保留；重提现有表达时补充早期出处，避免把回述误当新的要求。
- 每条交互独立保存，单条失败保留旧结果，其他条目可继续完成；重新开始会跳过依据未变的有效条目，明确选择重新整理才重做。追加未来消息不会使之前的分类失效。
- 自动注入不算真人表达；问答控件答复须严格匹配来源。多项答复的一次提交仍是一次人的表达，AI 问题本身不当作人的意见。
- 「看这次介入之前」从最近的原文向前展开；后续过程另行查看。模型分类只使用当前表达及之前的证据，不借用未来结果。
- 「全部会话」保留没有真人表达的会话入口，完整轨迹保留旧版手动解析、调用量估计、暂停续跑及原文快照。归档计数跟随当前导航口径，列表支持滚轮与 PageDown。
- 结果和原文快照由 DSH storage domain 保存，升级和重启后仍可读取；凭证由 DSH 管理，不另建服务。
- 「版本信息」同时显示界面与后台构建标识，用于确认实际运行代码。

本版借鉴本机已安装的 `dsh-context`（上下文洞察 0.84.0）在日期导航、会话定位、紧凑摘要与原文展开上的组织方式。它的事件与用量视图不等于人的介入分类；这里的分类另用 DSH 模型生成并核对引用，不复用其统计结果作为语义结论。当前没有介入率、周报或工作方式建议。

## 安装

要求 Node.js **24.9+**、DSH **0.2.1-rc.2、0.2.1-rc.5 或 0.2.2-rc.1**，以及 PATH 中的 pnpm（缺少时执行 `npm install --global pnpm@11.25.0`）。这三个内核版本均纳入原生安装、集成与浏览器测试矩阵，不需要版本豁免；其他版本需要重新验证。Desktop 外壳版本与内置 DSH 内核版本分别核对，不能将内置浏览器的 Electron 版本当作 DSH Desktop 版本。

在本仓库目录执行（PowerShell / bash 均可）：

```sh
git pull
npm ci
npm pack
dsh plugin --profile web add ./dsh-collab-journal-0.3.3.tgz
dsh web
```

已有 DSH Web 实例时，安装后重启它。在左侧点击「协作观察」，选择日期下的会话，点击「整理当天交互」，即可阅读分类、前因和具体贡献；未整理时也可直接看原话。需要模型归纳整段会话时，切换到「完整轨迹」后点击「解析轨迹」。这是安装到 DSH 的插件，无独立服务启动步骤。

`web` 指 DSH 的 Web profile。你运行自定义 profile 时，把安装命令的 `web` 替换为对应名称。桌面版请在该 DSH 实例的 **插件管理 → 添加插件** 中填写本地构建后仓库的绝对路径，安装到桌面实例；CLI 的 web profile 与桌面 profile 不共享安装。桌面壳本身尚未做自动化验收。

Desktop 更新后，完全退出应用（包括托盘）再重新打开。在「协作观察」页底展开「版本信息」，核对界面与后台版本都是 0.3.3，且构建标识一致。该标识由本次构建的源码内容生成，修改代码后重新构建会改变；仅查看安装器的版本号、禁用再启用插件，不足以证明宿主已加载新代码。这里无需重启操作系统。升级保留原 storage domain 与已生成的轨迹。

同版本反复构建时，不要覆盖同一路径的 tarball 后直接重装：本机 pnpm 曾报告“Already up to date”，重启后仍加载旧包。给每次构建使用不同的安装包路径（例如将 `.tgz` 文件名加上构建标识），再执行 `dsh plugin --profile web add <新路径>`，最后核对前后台标识。不要通过清空 profile 或 storage 来解决缓存。

若侧栏仍显示“AI 默认只取首尾回应”，先检查实际 profile 的 `cordis.patch.yml` 是否直接加载旧 `collaboration-observer` 文件路径。这是早期原型，与本包不同；应先备份配置，仅移除旧原型的加载项，再安装本包并重启。保留旧原型文件与数据，不要按安装器版本判断实际加载版本。

仓库尚未发布 npm 包，请使用上面的本地打包安装，不能直接运行 `dsh plugin add dsh-collab-journal`。升级后重新构建、打包、安装并重启即可。

卸载 Web 插件：

```sh
dsh plugin --profile web remove dsh-collab-journal
```

## 每日定时整理

在「插件设置」启用开关、选好每日时间后点「保存设置」。表单显示运行使用的时区和最近一次结果。关闭插件页面后仍可定时执行，DSH 宿主需保持运行。DSH 或电脑当天在设定时刻之后恢复，可以补跑当天尚未开始的任务。首次开启或修改时间从下一个设定时刻生效。

定时任务按每段会话已有的 DSH 模型整理介入，复用有效分类和原文依据。如果当天介入和总结均已是最新，会跳过模型调用。遇到正在运行的插件任务会等待；发生整理错误时，保留成功的介入和已有总结。退出中断的任务会显示在最近运行结果中，可手动继续整理。关闭开关后，已经写入的结果仍可阅读。待整理介入的原文或前文含已识别的本机 DSH 启动凭证时，该条自动整理会停止并显示原因，其余可处理的条目继续保存。

0.3.2 在 Mac 的 DSH Web 0.2.1-rc.5 上实际设为当地时间 11:37。到点后，DSH 配置的 GPT-6-Astra 先整理 1 条待处理介入，再更新覆盖 4 次表达的当日总结，各用 1 次模型调用，共 15.4 秒；原有 3 份结果标识一致。验收中发现时间框直接填值未同步到表单，改为监听输入事件，并重新安装和复验了实际保存、重开读回及后台构建标识。最终前后台构建为 `3054208dfae0`，定时后台与到点验证的构建逐字节一致（构建标识除外）。宿主重启后结果一致，当天未重复执行。验收后恢复默认关闭、21:00。

## 解析失败排查（0.2.1）

旧版“模型返回的节点或摘要格式无效”表示模型已返回 JSON，但节点 ID、摘要或细节校验失败；这条信息无法区分具体字段。0.2.1 会显示字段路径、限制和实际长度，例如 `items[0].summary 最多 180 字符，实际 181 字符`。

插件兼容缺省/null 的 details、单条字符串细节及多余空白；不截断摘要，不猜测错误 ID。其他 JSON/格式错误只重试当前批次，最多额外 2 次，带具体校验反馈并复用同一批原文。模型输入项顶层不再包含可能与输出 id 混淆的 nodeId、seq 或子摘要 id。

0.2.4 还兼容一个实测格式问题：模型已完整输出全部预期条目及 id、summary、details 数组，但仅遗漏最外层 `]}`。此时只追加这两个闭合符，再执行全部原有字段校验；不修改已有文字，不修补缺失条目、字段、内层语法或截断字符串。来源 seq 等标记位于历史证据文本内，不作为待输出的 id。

仍失败时，在错误提示中展开 **诊断信息**，提供其中的字段错误、模型路由、调用次数、耗时与停止位置。该诊断不含会话正文和模型原始输出；格式校验失败也会在 DSH 后台输出 `[dsh-collab-journal]` 日志及校验堆栈。有旧轨迹时继续展示，没有旧轨迹时明确提示尚未生成。

更新必须重新构建、安装并重启实际使用的 DSH 实例；只 `git pull` 不会更新已安装插件。修复覆盖已知格式失败分支，具体会话是否成功仍需使用你配置的真实模型复验。

若本地已有诊断补丁，先保存 diff 和未跟踪文件，在独立 worktree/副本测试上游版本，或逐项合并。不要用强制 checkout/reset 覆盖现有修改。允许为了定位问题增加局部日志、缩小测试输入或调整单个参数；每次记录假设、改动、重建后的构建标识、实测结果，再决定是否保留。临时原文日志仅保存在本地，回传最小脱敏证据。将字段校验放开或使用兜底合并属于行为变化，需单独记录，不能据此宣称原问题已修复。

## 使用与数据

模型由源会话最后一个 `request/header` 决定，旧记录则回退到最后一个模型回复的来源。模型已移除时会明确失败，请在 DSH 恢复该路由或用可用模型继续一次对话。没有模型记录的空会话须先完成一次 DSH 对话。

交互整理会把当前人的完整表达及选中的前文片段发送到该 DSH 模型服务；完整轨迹解析会发送所选会话的可读文本，与 DSH 当前模型配置的数据流相同。插件不读取 OpenCode 数据，不另存 API Key，不执行历史对话里的指令，也不向解析模型开放工具。

当日总结使用当天每次真人表达的完整文本，并带上已有且依据仍有效的交互分类与说明，无需先解析完整轨迹。说明中的引用标明原始时间与所属日期，跨日前文只作为背景，不当作当天进展。它按各会话当天首次表达的时间排序，复用第一段有模型记录的会话所用的 DSH 提供商和模型。这个模型会收到选定范围内各工作区的材料。生成前可查看模型，生成后可展开「总结范围与来源」核对模型、会话和表达数量。

当日总结发送模型前，会将本机 DSH 启动链接中的登录令牌及其复制引用替换为明确的隐藏标记，记录替换次数；其余表达保留。原始会话与原文阅读不改写。这是针对已知启动链接的保护，不是通用的秘密检测器。

「生成当日总结」与「更新当日总结」可随时手动执行。开启每日定时整理后，宿主也会在设定时间按需更新总结。总结按日期、时区和归档范围分别保存。追加当天的表达后，点击「刷新会话」会提示已有总结待更新。更新失败时，原有总结继续可读，失败原因可在总结下方查看。关闭并重启 DSH 后仍可查看已保存的总结。

插件数据使用 `dsh_collab_journal` domain，由 DSH 管理；默认 JSON 后端位于 `$DSH_HOME/storages/dsh_collab_journal.json`。原始 DSH 会话保持不变。分片和合并批次通过校验后保存到同一 domain 的 checkpoints 表；续跑仅复用原文指纹、模型路由及解析规则一致的进度，原文或模型变化时从头解析。重新打开 DSH 后点击「继续解析」，不会因浏览或重启自动发起模型调用。每次成功解析保存新结果并清除本次进度；原文快照按会话和内容指纹版本化，以免旧摘要引用了新消息。卸载不会主动删除这些记录。

## 验证

```sh
npm ci
npm test
npm install --prefix .dsh-test/runtime --no-save @deepseek-ai/dsh@0.2.2-rc.1
npm run test:integration
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install chromium
npm run test:browser
```

集成测试实际启动已安装的 DSH，在隔离的 `DSH_HOME` 中通过 `dsh plugin --profile web add` 安装本项目 tarball，使用 DSH 原生 session/workspace/persistence/LLM/storage 服务。覆盖跨日旧会话、合并边界、长工具日志尾部、快照、失败重试、鉴权、实际构建标识和重启后的持久会话读取。浏览器测试在真实 DSH 页面中点击原生侧栏入口、解析、展开原文、切换 workspace、搜索并检查窄布局，以及 12 条未归组会话中 7 条归档的过滤提示、滚轮和键盘访问。CI 在 Windows/Linux 分别运行三个 DSH 内核版本的集成测试，并在 Linux 对三个版本运行浏览器测试。

测试模型是通过 DSH LLM 服务注册的确定性适配器，用于验证协议和链路，不代表真实模型的摘要质量。真实模型质量需要结合你的会话核对。

0.3.3 在 Mac 的 DSH Web 0.2.1-rc.5 上验证，界面和后台构建均为 `77a91feae81b`。在真实页面触发 GPT-6-Astra 整理两轮专用会话，追加第三轮后显示有新内容，并保留前两条整理。再次解析得到 6 个轨迹节点。另一段含 4 次工具调用的会话得到 8 个节点，阅读时可分别核对失败、独立验证通过、部署未执行及线上状态未知。冷重启后，14 个节点的原文窗口、7 份介入和当日总结构成及文本均与重启前一致。浏览器回归另核对了失败保留、窄布局及归档末条的滚轮和 PageDown 可达性。

## 当前限制

仅解析文本。附件保留类型提示与原事件引用，不识别图片、音频内容。模型归纳仍可能失真，摘要与事实应通过原文核对。工具已经在 DSH 日志中被截断的部分无法恢复。

本机超长样本的完整轨迹已跑完，但独立语义复核仍发现 5 个 AI 节点、7 处细节或历史归属偏差，不能把“解析完成”当作语义准确性通过。默认「我的交互」使用独立的前文原始证据生成分类和说明，不使用这些旧摘要推断介入原因；完整轨迹的上述偏差仍然存在。具体证据与验收边界见[长会话记录](docs/mac-long-validation-2026-11-13.md)。

交互整理每条最多读取三轮，累计提供的原文最多 24,000 字符（不是整个历史都已读），每轮格式纠正最多两次，同一任务最多两条并行。证据不足须标记未知或未判定；当前人的表达本身超过预算会明确失败，不截断。证据面板显示实际读取范围。单条成功结果可复用，单条内部尚无分轮断点。历史快照暂不自动清理。

当日总结的整份输入（含会话信息、完整表达与已有交互说明）上限为 48,000 字符，格式纠正时也计入新增反馈。超限会提示实际长度并停止，本次不会截断或跳过表达。模型输出格式无效时最多额外纠正两次，仍不合格则显示失败。日期列表与当日总结尚无增量索引，初次读取与完成后的核对需要扫描会话日志，会话较多时可能较慢；总结运行中的状态刷新复用本次输入，不反复扫描。

完整轨迹当前一次只解析一个会话，同一阶段最多三批并行，每次调用 90 秒；不再设置整体十分钟截止，允许闲时持续运行。大对话可能需数小时与数百至上千次调用，解析前可查看调用量估计（不含格式重试）。可离开插件页面，但须保持 DSH 宿主运行；暂停、报错或退出时保留已完成批次，之后手动继续，可能重做未成功保存的在途批次（最多三批）。完整轨迹由用户手动发起。原独立应用保留在 Git 历史中，批注暂未移植到此插件版本。
