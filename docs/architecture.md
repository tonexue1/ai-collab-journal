# DSH 插件架构

## 约束

这是 DSH 原生插件。会话、workspace、模型、凭证、持久化、前端容器都由 DSH 提供。插件只负责协作轨迹的组织、摘要和呈现。

## 接入

| 工作 | DSH 接口 | 插件模块 |
| --- | --- | --- |
| 安装与激活 | `dsh.bundle.patch`，Cordis 生命周期 | `cordis.patch.yml`、`src/index.mjs` |
| 完整会话 | `sessionQuery.listSessions/readSession`，包含 live 与 persisted | `src/service.mjs` |
| Workspace | `workspaceRegistry.list()` 的 ID、`sessionIds`、归档集合 | `src/service.mjs` |
| 解析模型 | `llm.prepareCall` + 原会话 provider/model + `BlockAssembler` | `src/model.mjs` |
| 持久化 | `storageDomain.open`，`dsh_collab_journal` domain | `src/domain.mjs` |
| 通信 | `connection.fetch.register`，DSH 原生鉴权与来源校验 | `src/index.mjs` |
| UI | DSH 模块工厂、`sidebar.panellist`、`main` slot | `src/client.jsx`、`src/style.css` |

前端与 DSH 共用 React 实例，通过 `window.__ModuleLoader__` 加载。CSS 限定在插件根节点，使用 DSH 主题变量、容器查询适配宿主主栏宽度。卸载时撤销路由、槽位与样式，取消解析并关闭 domain。

支持并测试 DSH 0.2.1-rc.2、0.2.1-rc.5、0.2.2-rc.1；宿主安装无需版本豁免。构建时将 package、构建脚本及 src 内容的哈希同时嵌入 host/client，目录 API 返回后台实际标识，界面可核对二者。存储结构保持 domain version 1，不迁移或清除旧报告。

## 从人的表达进入

`days` 读取原生会话中严格认定的真人表达，用指定 IANA 时区及每条表达的时间分日。先对完整会话建立锚点与前后范围，再按日期过滤，同一会话可以出现在多天；跨午夜的前文仍可读取。无效时间单列计数，不用会话创建或更新时间代替。日期导航的会话数只包括有人表达的会话，「全部会话」保留其他入口。

`interactions` 与 `interactionContext` 是只读操作。每次人的表达由原始 seq 形成稳定锚点；前文范围包含最近的 AI 过程及上一请求，连续人的表达仍独立。前文分页从最近处向前，后文单独读取。来源索引只连接明确且唯一的调用与结果，保留历史替换、重放来源；工具返回不自动等于成功。实时原文分页绑定源指纹，变化时要求刷新。

`analyzeInteractions` 按选择的日期/会话或单个锚点手动整理；`src/interventions.mjs` 先提供当前人的完整表达、上一请求、附近 AI 和工具证据，允许模型用 seq 或原文关键词补读。当前 AI 过程里的非成功 turn/end 必须完整优先提供，预算不足即明确失败；较早完整短表达在当前文字中重现时，补充至多三条早期出处。重现只是文字关系，可能是引用，也可能是中断后的重提，不由程序预判意图。每条最多三轮、累计原文 24,000 字符，片段带 seq/offset/totalChars 和覆盖区间，不能把未读部分当作不存在。当前人的表达超预算即失败，不截断。每轮结构错误最多两次纠正，不新增传输重试。

输出是标题、最多三个类别、此前情况、人的具体贡献及引用。引文只能来自实际提供的连续区间且不晚于锚点，贡献须引用当前人的原话。格式和逐字引用通过不代表推论一定正确，界面明确标作 AI 整理；证据不足明确未知或未判定。普通新任务不等于 AI 失败，人的要求不能写成已经实现的成果。

每个锚点的依据指纹覆盖当前表达及完整此前来源、算法版本；后来追加的内容不使旧结果失效，之前的材料变化则标记 stale。新表仍追加在 v1 domain：`interaction_sources` 每个会话源指纹只保存一份完整快照，`interaction_versions` 保存不可变结果、实际已读片段及覆盖信息，`interaction_latest` 指向最近成功版本。按快照→结果→最新指针顺序发布，失败保留旧结果。`interactionEvidence` 只提供当时已读/引用来源的完整原文及当前人的表达，永不越过该锚点；它不依赖后续 live 消息。

交互整理与完整轨迹共用一个任务槽，交互内部最多两条并行。完全相同的在途请求可复用，模式或范围不同返回冲突；单条失败不阻止其他条目保存，取消或卸载等待所有在途调用和写入结束。重新整理默认跳过依据未变的结果；用户明确重做才覆盖最新指针。尚不生成介入率或自动化能力评分。

## 事实与摘要的边界

程序读取完整 raw event log，保留每次 `source.kind === 'user'` 的真人表达。成功的 ask_user_question 控件结果及 user-question-reply 迟到答复，只有在 callId、question ID 和答复结构均匹配时才作为人的表达；迟到答复还核对 answered 来源、正文类型、工具名和问题内容；问题标明来自 AI，选择/自填文本标明来自人，原始工具事件完整保留。未匹配、错误或含糊结果仍作为工具记录，不猜测来源。自动注入的上下文不制造人的介入。AI 的连续回复、工具调用/结果和失败结局归入相应节点。来源序号、角色、时间、工具次数由程序计算，模型只能填写 summary/details。

同一节点内按原顺序合装短记录，每片 text 的 JSON 序列化内容最多 2400 字符，包含 seq/type/role/offset 和转义，不跨人的表达边界。长条目保留所有片段及尾部，Unicode 字符不拆断。每次至多 4 片，先归纳各片，再在同一节点内分层合并。首层及同节点同层的独立合并组最多三路并行，结果始终按源顺序回填；节点间和合并层间保留依赖顺序。模型输入每项只暴露一个待复制的 id，来源标记放在 text 内，内部 nodeId 和子摘要 id 不参与模型输入。校验输出 ID 覆盖、唯一性、摘要与细节长度。工具调用不等于成功，计划不等于结果；提示词明确要求保留未知与失败。

`src/output.mjs` 给出不含正文的字段级错误。details 缺省/null 变为空数组，字符串变为单项数组，文本空白规范化；超长文本不截断，错误 ID 不按位置猜测。格式校验失败时，只对当前批次附加校验反馈重试，最多额外两次，覆盖分片和合并两个阶段；传输、鉴权、超时、取消等错误不进入格式重试。每次调用有独立截止时间；不设置整个长任务的截止时间。耗尽重试后保留失败阶段、模型路由、调用次数、具体字段问题，UI 可展开诊断信息；后台仅为格式校验错误记录受控消息和堆栈，不记录原始模型响应。

针对真实响应仅漏最外层 `]}` 的情况，解析失败分支仅尝试追加这两个字符；要求唯一根字段 items、条目数精确、每项已有 id/summary/details 数组，再通过全部原有校验。未返回的条目、字段或字符串内容绝不补写，其他语法错误仍交给原纠正流程。此兼容不改变已成功校验摘要的语义，故不使已有 v5 断点失效。

`checkpoints` 在同一 v1 domain 中保存已校验的分片/合并输出，不保存失败响应。稳定任务位置、输入内容及提示词版本共同定义批次缓存键；源指纹、模型路由和解析版本不匹配时弃用旧进度。校验通过的结果进入单写队列，实际写入时基于最新已提交缓存构建完整快照，避免并发覆盖；每批先 await 持久化再推进，读取缓存仍执行结构校验。首个错误会取消其余工作，等待所有请求与已接受的写入结束后才释放任务，诊断固定在首个失败批次。jobId 标记已发布的任务，即使清理进度失败，下一次主动重新解析也不会复用已完成任务。旧 v1 存储新增空表即可兼容，不清除 reports/versions。

原始材料的内容指纹定义 snapshotId。`versions` 保存解析时的原文与结果，`reports` 指向最近成功结果。先写版本，再替换当前结果；中途失败、停止或模型输出不合法时，当前结果不变。浏览旧结果时按旧 snapshotId 取上下文。会话新消息只标记 stale，不悄悄覆盖旧摘要。

长任务允许持续运行，每个模型调用最多 90 秒；一次只允许一个解析，重复点击同一会话复用当前任务。UI 异步响应按会话选择版本隔离，避免切换后显示上一会话结果。读取目录和详情不会调用模型。

## 已知限制

- 真实模型可能归纳错误，原文引用是核查入口，不自动证明摘要正确。
- 图片等非文本附件只显示提示；不恢复源日志已经丢失的内容。
- 目录完整读取开销随日志规模增长，暂未增加自有索引或后台采集。
- 历史快照尚无清理策略；重启会结束未完成的调用，但保留最近成功结果和已完成批次；重新打开后手动继续。
- 原生安装、集成和浏览器覆盖 DSH 0.2.1-rc.2、0.2.1-rc.5、0.2.2-rc.1 的 Web profile；Desktop 外壳及真实提供商仍须本地验收。
- 在途批次完成并保存前中断，可能需要重复最多三批调用；原文、模型或解析规则改变时不混用旧进度。
- 日报、周报、定时筛选、人工批注尚未作为原生插件实现。

## 验收方式

纯函数及服务测试覆盖来源区分、长日志、输出校验、去重、错误保留、证据不可变。集成测试安装真正的 tarball、启动真实 DSH，使用原生持久会话与 workspace。模型使用 DSH 注册的确定性适配器，明确与真实模型语义质量分开。浏览器测试加载真实 DSH Client，执行侧栏进入、解析与原文操作，输出桌面及窄栏截图。
