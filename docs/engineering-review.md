# 基于项目哲学的工程评审

评审日期：2026-11-07。代码基线：`eb185b826c3d131e26b87558be2c4052787e8f34`。

依据：[为什么做协作观察](philosophy.md)。三个独立的 AI 工程评审分别检查材料与归纳、人工判断与版本、日常运行与交互，随后合并意见并复核关键情景。

本轮只评审与复现，没有修改业务实现。下文的改法均为建议。复现使用合成材料、临时数据和隔离配置；没有使用真实工作对话，没有完成真实模型的语义验收。CLI 配置探测不调用模型。

## 总体判断

现有的本地 SQLite、原文快照、独立批注、失败记录和定时执行，适合当前用途，应当保留。最需要补的是同一件事的持续追踪，以及人的判断如何影响后续结论。

当前实现以“某天的一批消息生成一份报告”为主。实际工作中的一件事却可能跨片段、跨日期，用户也会在报告生成以后纠正它。实现需要表达这些变化，才能落实“把事情调查清楚，再修正自己的认识”。

| 工程视角 | 优先解决的问题 | 建议保持的边界 |
|---|---|---|
| 材料与归纳 | 事件结局不能被批次、日期切断；周比较不能丢掉条件和结果 | 先用清楚的事件材料与小规模语义验收，不引入检索平台 |
| 人工判断与版本 | 纠错应明确生效；旧结论应指向当时证据；材料变化应提示重看 | 使用少量状态和版本字段，不建设复杂审计系统 |
| 日常运行与交互 | 保存不能误报；旧日故障不能堵住新日报；模型配置来源应明确 | 保留本地调度与现有应用结构 |

P1 表示影响事实可信、个人思考保存或持续复盘，应在下一轮真实试用前优先处理；P2 表示明确的接入支持缺口。验收缺口与已复现的程序缺陷分别说明。

## 第一组：把一件事的来龙去脉接起来

### R1 · P1 · 事件生命周期被批次和日期截断

**已复现。** 昨天 23:59 用户要求修复并验证，今天 02:00 昨日日报被标为完整，03:00 助手才给出测试失败。今天分析虽然包含这些消息，但没有今天的用户锚点，后续结果无法提取为合法事件；昨天的完整日报又被补跑逻辑跳过。长工具日志将指令与结果分到不同批次时，也会遇到类似限制。同锚点合并只追加证据，不能用后续结果修正前面的归纳。

证据：[当天锚点限制](../src/analysis.mjs#L71)、[事件合并](../src/analysis.mjs#L86)、[按日期设置完整状态](../src/engine.mjs#L46)、[跳过完整日报](../src/engine.mjs#L78)。

**最小改法：** 分开处理“新的用户介入”和“既有事件的后续进展”。事件保留原介入日期，结果另记发生时间。采集后比较消息及工具内容的变化，只将受影响事件标为待更新。材料先围绕一次介入组织，超长时仍可分片，但要保留事件联系，在事件层统一归纳。仅向每片重复用户消息，无法解决首次结果被固定的问题。

**验收：** 上述案例始终只有一件原日期事件，后来补上失败结果及时间；不能增加一次今天的用户介入。插入长日志后，结果应保持一致。没有新材料时不重复更新。

### R2 · P1 · 周比较的输入丢掉了已有的关键材料

**已复现输入差异丢失。** 两天事件的标题、分类、摘要都为“要求补齐验证”，一天成功、一天失败。当前周输入没有传入已保存的 `intent`、`intervention`、`outcome`、`evidence`；这两项事件除 ID 外可以完全相同。不能据此断言模型必然误判，但它已经失去比较结果的材料。

证据：[周分析输入构造](../src/engine.mjs#L56)。

**最小改法：** 周输入使用经过人工修正的有效事件，至少保留意图、介入、结果及来源引用；必要时附相关原文片段。候选解释应交代适用条件、反例与未知。材料超预算时明确报告，不能静默去掉结果或关键条件。

**验收：** 同类介入、相反结果的事件，不能归纳成“这种做法总是有效”；同名现象、不同任务条件，也不能仅凭分类相同就认定原因相同。

### R3 · P1 验收缺口 · 需要检验模型是否形成了有根据的认识

**确认现状。** 现有集成测试用固定模型响应验证链路，不能辨别正常决策与纠偏，也不能证明引用支持结论。真实模型的总结质量仍待验收。

证据：[固定模型响应](../test/opencode.integration.mjs#L42)、[事件结构与引用校验](../src/analysis.mjs#L57)。

**最小改法：** 建立一组小规模语义验收材料。逐例标出必须保留的事实、禁止作出的断言、允许的未知，保留表达上的合理差异。覆盖正常决策、方向纠偏、跨日结果、长日志结局、同类异因和证据不足。公开仓库使用合成或经确认可公开的材料；真实工作样本保留在本地。实际运行记录模型和规则版本，并由人核对。

**验收：** 分别列出漏事件、错结果、无依据因果的例子，以及人工判断；不能以 JSON 合法、流程成功替代内容验收。已有工程测试继续保留。

## 第二组：让人的判断成为明确、可追溯的状态

### R4 · P1 · 批注能留下，纠错的效力没有明确表达

**已复现。** 在批注写“实际测试失败”后，事件的结果字段仍是“已完成”。当前仅有笔记、分类和关注标记，不能明确拒绝误判、修改事实或补入遗漏。模型是否采用笔记，依赖下一次理解。

证据：[批注字段](../src/store.mjs#L58)、[人工核对界面](../public/app.js#L41)、[日汇总采用笔记的方式](../src/engine.mjs#L39)。

**最小改法：** 在现有人工记录上增加可选的决定与字段修正，例如 `decision: unreviewed/keep/reject`、`overrides: {summary, outcome}`。统一通过 `effectiveEvent()` 生成页面、导出、日/周分析所用的当前事件，保留原 AI 提案。补入人工事件时记录 `origin: human`，重跑不删除它；从当天会话列表也能进入原文并补漏。

**验收：** 拒绝的事件重跑后不重新成为当前事实；修改结果后，页面、导出与模型输入一致；人工补入的事件不会被下一次提取抹去。未操作的事件仍可正常阅读，不要求用户每天逐条审批。

### R5 · P1 · 旧周报的证据链接会漂移到新版本

**已复现。** 周报依据 V1 事件生成，只保存事件 ID。同一锚点重跑会覆盖事件 payload 与 snapshot 指针。随后点击旧周报的证据，得到 V2 原文；V1 快照虽然还在，旧周报没有绑定它。

证据：[同 ID 覆盖事件](../src/store.mjs#L50)、[按当前事件查证据](../src/server.mjs#L15)、[周报证据点击](../public/app.js#L90)。

**最小改法：** 机器提案增加简单的 `revision`，人工决定记录 `basedOnRevision`。每份周报保存采用的事件字段、版本与原文 snapshot ID，查看旧报告时使用当时的依据。同锚点内容改变应提示重新核对，不能静默沿用先前确认。锚点变化产生新 ID 时，保留旧批注，由用户明确决定是否关联。

**验收：** V2 日报生成后，V1 周报仍能回看 V1 依据；新旧解释可区分，旧批注仍可查。用户需要重新核对的只是发生实质变化的内容。

### R6 · P1 · 材料变化没有使相关总结过期

**已复现。** 修改批注或重跑日报不会使完整周报失效，`due()` 继续跳过它。旧事件退出当前日报后，只要有批注，还会与当前事件无历史标记地混入周输入；锚点变化时，同一经历可能以新旧两项进入比较。

证据：[历史事件筛选](../src/store.mjs#L45)、[周输入混入历史事件](../src/engine.mjs#L56)、[完整周报直接跳过](../src/engine.mjs#L79)。

**最小改法：** 日期维护材料版本，事件、人工修正或补漏变化时更新版本。日报概况和周报记录所依据的版本；不一致就显示待更新，夜间刷新受影响的汇总。当前事实只采用有效事件，历史笔记作为明确标注的背景；需要保留为当前事实时，由用户明确选择。

**验收：** 人工修正后，相关汇总显示待更新；刷新后与新材料一致，再次补跑不重复生成。被替换或否定的事件不能继续构成新的周模式。旧报告作为历史保留其原有依据。

## 第三组：保证每天用得下去

### R7 · P1 · 保存期间继续输入，会把未保存内容误标为已保存

**已复现。** 写“第一版”并保存，请求返回前继续写“第二版”。数据库只收到第一版，但响应返回后无条件清除 `dirty`，页面显示保存成功，离开时不再提醒。复现结果为 `visibleText=第二版, savedText=第一版, dirty=false`。

证据：[保存响应处理](../public/app.js#L45)、[编辑与离开保护](../public/app.js#L93)。

**最小改法：** 编辑增加递增版本，保存时记录事件 ID 和版本。只有当前事件、编辑版本都未改变，响应才可清除未保存状态；否则说明此前内容已保存、当前修改仍未保存。连续保存先串行执行，或由服务端按修订号拒绝过期写入，避免旧请求覆盖新内容。

**验收：** 人为延迟响应，测试继续输入、切换事件、两次保存逆序完成。最新文本始终能够保存，未保存部分不会失去离开提醒。

### R8 · P1 · 一个旧日期失败会阻断后面所有日报

**已复现。** 三天等待补跑，第一天因汇总材料过大失败，后两天不会被尝试。下一夜仍从同一个失败日期开始，形成持续阻塞。另外，每个待补日期都会重新全量采集项目历史；重复采集已由代码确认，真实大规模耗时尚未测量。

证据：[补跑循环](../src/engine.mjs#L76)、[每日报再次采集](../src/engine.mjs#L26)、[会话逐个导出](../src/opencode.mjs#L105)。

**最小改法：** 区分全局故障与单日故障。认证、整体采集失败等全局问题停止整批；单日材料或输出问题记录失败后继续其他日期。最后明确报告成功、失败、未尝试项目，有失败时保留失败退出状态。一次补跑尽量共用一次成功采集的快照及覆盖信息。

**验收：** 第一天材料过大，后两天仍成功；重跑只处理缺口。全局模型认证失败时不对每一天重复发送相同请求。周报如使用不完整日期范围，仍明确显示缺失日期。

### R9 · P2 · 项目里可用的模型配置不一定在分析目录生效

**真实 CLI 配置探测确认。** 将合成 provider 与默认 model 仅放在工作项目配置中，OpenCode 1.19.5 在该项目能够解析它们，在独立分析目录则没有这些配置。全局配置用户不受这个结论直接影响。现有集成测试使用全局 XDG 配置，没有覆盖这个差异；`doctor` 也仅探测版本和帮助。

证据：[独立分析目录](../src/config.mjs#L36)、[模型执行位置](../src/opencode.mjs#L86)、[doctor](../src/cli.mjs#L39)、[集成测试配置](../test/opencode.integration.mjs#L62)。

**最小改法：** 明确复盘模型的配置来源，首先说明全局配置的支持范围。若需要复用项目连接，显式选择来源，只接入必要的模型连接配置，保持分析目录的工具禁用约束。`doctor` 显示经过脱敏的实际 provider/model 及来源，不能仅凭 CLI 可运行就声称模型已就绪；不静默复制整个项目的插件和权限配置。

**验收：** 覆盖全局 provider、仅项目级 provider、显式模型选择三种情景，检查实际模型与禁用工具约束。缺失配置应在开始分析前给出可操作的错误，不悄悄切换模型。

## 合并后的实施顺序

这些建议应共用一套轻量的事件版本与人工决定，避免每个模块各建一套状态。

1. **先修容易损失材料的具体缺陷。** 处理保存竞态与单日失败阻塞，明确模型配置范围；同时补跨日、长日志、延迟保存等复现用例。分别按 R7、R8、R9 验收。
2. **让一件事得到完整、可修正的表达。** 处理 R1，补足 R2 的周输入；落实 R4 的有效事件读取与人工补漏。此时用少量语义样本检查事实、结果和遗漏，不等界面完善后再验收。
3. **固定依据，接通结论更新。** 联合实现 R5、R6，确保版本、原文快照、人工决定和汇总采用的材料一致。原始消息、机器解释、人的判断分别保留。
4. **回到真实使用中检验。** 完成 R3 的真实模型验收，再读一次实际忙碌日，记录核对耗时、误判与不必要的返查。发现问题后缩小范围修正，不以新增分类或组件代替验证。

暂缓自动生成 Skill、复杂跨事件匹配、向量记忆、消息队列、实时监听和额外 agent 编排。当前优先把事实、人的纠正以及后续结论之间的联系做可靠。
